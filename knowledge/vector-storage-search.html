04Hybrid Search — Semantic + Keyword

Vector Search

เก่งเรื่องความหมายและ synonym เช่น “ของยังไม่มาส่ง” สามารถเจอเอกสารเรื่อง “ติดตามพัสดุ” ได้แม้คำไม่ตรงกัน

Keyword / BM25

เก่งกับรหัส ชื่อเฉพาะ หรือข้อความที่ต้องตรง เช่น SKU, error code, เลขอ้างอิง

Hybrid

ค้นทั้งสองทางแล้วรวมอันดับ เช่น RRF เพื่อลดปัญหาที่ semantic หรือ keyword อย่างใดอย่างหนึ่งพลาด

Rerank

ดึง candidate มากก่อน แล้วให้โมเดล/algorithm ที่ละเอียดกว่าจัดอันดับใหม่ก่อนใส่ context

แนวทาง: ถ้าโดเมนมีทั้งภาษาธรรมชาติและรหัสเฉพาะ ให้ทดสอบ hybrid search กับชุดคำถามจริงแทนการเลือก vector-only จากความรู้สึก

05Index — ทำไมไม่คำนวณทุกแถว

แนวทางหลักการเหมาะกับ
Flat / Brute Forceเทียบ query กับทุก vector ได้ exact resultข้อมูลไม่ใหญ่มากและใช้เป็น baseline วัด recall
HNSWสร้างกราฟเพื่อนบ้านแล้วเดินจากชั้นหยาบสู่จุดใกล้vector จำนวนมากที่ต้องการ query เร็วและยอมรับ approximate search
IVFแบ่ง vector เป็น cluster แล้วค้นบาง clusterต้องการ index ที่ build/เก็บต่างจาก HNSW
Quantizationบีบ representation เพื่อลด RAM/storageข้อมูลใหญ่มากและยอมแลก recall บางส่วน

วัด Recall: หลังสร้าง ANN index ให้เทียบผลกับ brute-force บนชุด query จริง เพื่อรู้ว่าความเร็วที่ได้แลกกับ neighbor ที่พลาดไปเท่าไร

06SQL และ C# — เก็บและค้นจริง

-- แนวคิดตาราง
CREATE TABLE chunks (
  chunk_id   BIGINT PRIMARY KEY,
  doc_id     TEXT NOT NULL,
  section    TEXT,
  content    TEXT NOT NULL,
  acl        TEXT NOT NULL,
  model_ver  TEXT NOT NULL,
  embedding  VECTOR(1536) NOT NULL
);

-- Query: filter ก่อน แล้วค่อยเรียง distance
SELECT chunk_id, content
FROM chunks
WHERE acl IN ('public')
ORDER BY embedding <=> @query_vector
LIMIT 5;
