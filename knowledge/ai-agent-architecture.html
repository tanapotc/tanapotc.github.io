01LLM, Agent, Tools

LLM

รับ context แล้วคืนข้อความหรือ tool call ตัวมันเองไม่มี state และไม่ได้ลงมือทำ side effect โดยตรง

Agent

LLM + loop/orchestrator + tools + memory + guardrails ที่ทำให้ระบบเดินต่อหลายขั้นจนบรรลุ goal

Tools

ฟังก์ชันที่มีชื่อ คำอธิบาย และ parameter schema ให้โมเดลใช้ตัดสินใจว่าจะเรียกเมื่อไร

จุดสำคัญ: permission, validation, idempotency และวงเงินต้องบังคับใน code/tool layer ไม่ใช่หวังให้ prompt ห้ามอย่างเดียว

02MCP — มาตรฐานให้ Tool ใช้ซ้ำได้

Model Context Protocol ลดการเชื่อมต่อแบบ N agents × M systems โดยให้ระบบต้นทางประกาศความสามารถครั้งเดียว แล้ว client หลายตัวคุยด้วยมาตรฐานเดียว

ก่อน MCP

Support, Dev และ Ops agent ต่างคนต่างเขียน integration ไป Jira, SQL และ GitHub เกิด auth/schema/error handling ซ้ำหลายชุด

หลัง MCP

แต่ละระบบเปิด MCP server และประกาศ Tools, Resources, Prompts; agent เชื่อมผ่าน MCP client

Tools

การกระทำที่โมเดลเรียกได้ เช่น query order หรือ create issue

Resources

ข้อมูลที่อ่านได้เพื่อใส่ context เช่น schema หรือ policy document

Prompts

template ที่ server เตรียมไว้เพื่อบอกวิธีใช้ข้อมูลหรือ tool ให้ถูกบริบท

Transportใช้ stdio เมื่ออยู่เครื่องเดียวกัน และ HTTP เมื่อเป็น service กลาง
Identityให้ server ทำงานตามสิทธิ์ผู้ใช้/tenant ไม่ใช่ service account ที่ทำได้ทุกอย่าง
Destructive toolsแยกและทำให้ client รู้ว่าต้อง human approval
Prompt injectionผลจาก ticket/email/document ภายนอกถือเป็นข้อมูล ไม่ใช่คำสั่ง
ใช้ MCP เมื่อไรคุ้มเมื่อ tool เดียวถูกใช้จากหลาย agent/client; ถ้าอยู่ในแอปเดียว function calling ตรง ๆ อาจง่ายกว่า

03Memory — LLM ไม่จำ ระบบต้องจำแทน

Working / Context

ข้อมูลที่อยู่ใน prompt รอบนี้และหายเมื่อ call จบ

Conversation + Summary

history ของงานปัจจุบันและสรุปส่วนเก่าเพื่อลด token

Episodic / Semantic / Procedural

งานที่เคยทำ, facts ระยะยาว และวิธีทำงานที่ version ได้

History โตตัดส่วนเก่า สรุป และย่อ tool result ใหญ่หลังใช้แล้ว
Context ใหญ่เกินอย่าใส่ทุกอย่างเพียงเพราะ window ใหญ่; เลือกเฉพาะที่เกี่ยวข้อง
ข้ามผู้ใช้memory ทุกชั้นต้อง key ด้วย user/tenant
ข้อมูลอ่อนไหวredact ก่อนเก็บ และควรมีวิธีดู/ลบ facts ที่ระบบจำ

05Orchestrator — ตัวที่เป็น “Agent” จริง ๆ

Free Loop

LLM เลือก tool และเส้นทางเอง ยืดหยุ่นกับงานเปิด เช่น research/debug แต่เส้นทางและ cost คาดเดายากกว่า

Graph / State Machine

โค้ดกำหนด node/edge เช่น classify → retrieve → draft → check → review → send ทำให้ test, checkpoint และ human-in-the-loop ชัดขึ้น

while (state.Step != Step.Done)
{
    await checkpoint.SaveAsync(state, ct);
    state = state.Step switch
    {
        Step.Classify => await Classify(state, ct),
        Step.Retrieve => await Retrieve(state, ct),
        Step.Draft    => await Draft(state, ct),
        Step.Check    => await CheckAndRoute(state, ct),
        Step.Review   => await WaitForHuman(state, ct),
        Step.Send     => await Send(state, ct),
        _ => state
    };
}

ไม่ว่าใช้แบบไหน: ต้องมี max turns, max cost, tool timeout, policy check และ state นอก process เพื่อ resume ได้

06Multi-Agent — แยกเมื่อ Agent เดียวเริ่มสับสน

Supervisor

ตัวกลางแจกงานให้ worker และรวมผล ควบคุมง่ายแต่ supervisor อาจเป็นคอขวด

Handoff

agent ส่ง ownership พร้อมสรุป context ไปให้อีก agent เหมือนโอนสายระหว่างแผนก

Blackboard

หลาย worker อ่าน/เขียน shared state หรือ task board เดียวกัน ต้องมี ownership ป้องกันงานซ้ำ

Loopกำหนด hop limit ป้องกัน A ↔ B ส่งงานกันไม่จบ
Costส่ง summary แทน history ทั้งก้อน และวัด token ต่อ workflow
Truthมี single source of truth เช่น DB/task board ไม่เชื่อคำบอกเล่าระหว่าง agent อย่างเดียว
MCP vs A2AMCP = agent ↔ tools/data; A2A = agent ↔ agent โดยเฉพาะเมื่อข้าม process/องค์กร

เริ่มจาก Agent เดียวก่อน แล้วค่อยแยกเมื่อ tool/prompt ของงานต่างชนิดเริ่มขัดกัน หรือต้องการ worker/reviewer ที่แยกบทบาทจริง

07Observability & Evals

ระดับควรดูอะไร
Traceprompt จริง, output, tokens, latency, tool args/result และ session/user id ของทุก LLM/tool call
Retrieval Evalชุดคำถามพร้อม chunk ที่ควรเจอ แล้ววัด recall@k / ranking metric
Answer Evalgolden set + rubric และ human review บางส่วน
Trajectoryตรวจลำดับการใช้ tool/approval เช่นต้อง lookup ก่อน write และไม่เกินจำนวน turn
Regressionรัน eval ทุกครั้งที่เปลี่ยน prompt/model/tool เพราะ prompt ก็คือ artifact ที่ต้อง version และ test

08Reference Architecture บน .NET

Shop.Agent.Api/          // endpoint, auth, streaming
Shop.Agent.Core/         // orchestrator, graph, guardrails, state
  Steps/                 // Classify, Draft, Check ...
  Prompts/               // prompt files ที่ version ได้
  Policies/              // permission / approval / limits
Shop.Agent.Tools/        // tool layer / MCP server
Shop.Agent.Knowledge/    // ingest + retrieval
Shop.Agent.Memory/       // sessions + facts + summary
Shop.Agent.Evals/        // golden set + trajectory tests

Microsoft.Extensions.AI // LLM / embedding abstractions
ModelContextProtocol    // MCP client/server
OpenTelemetry           // tracing

ลำดับสร้าง: LLM call + eval → เพิ่ม RAG/tool ที่จำเป็น → เพิ่ม loop เมื่อขั้นตอนไม่ตายตัว → memory เมื่อข้าม session → MCP เมื่อ tool ต้องใช้ซ้ำ → multi-agent เมื่อ Agent เดียวไม่พอ

สรุปใจความสำคัญ
