01Component เดียวกัน เขียน 3 แบบ

ตัวอย่าง Counter เดียวกันช่วยให้เห็นว่าทั้งสามวาง state, template และ logic ต่างกันตรงไหน

React

JSX · function component · Hooks
function Counter({ start = 0 }) {
  const [count, setCount] = useState(start);
  const over = count > 10;

  return <>
    <button onClick={() => setCount(count + 1)}>+1</button>
    <p>{count}</p>
    {over && <p>เกิน 10 แล้ว</p>}
  </>
}

Angular

@Component({

  <button (click)="inc()">+1</button>
  <p>{{ count() }}</p>

 `
})
export class CounterComponent {
 count = signal(0)
 over = computed(() => this.count() > 10)
 inc() { this.count.update(c => c + 1) }
}

03เริ่มโปรเจกต์ — framework เลือกอะไรให้บ้าง

React

npm create vite@latest my-app -- --template react-ts cd my-app && npm install && npm run dev
src/ ├── main.tsx ├── App.tsx ├── App.css └── index.css

ฐานเริ่มต้นเล็กมาก Router, data fetching และ global state เลือกเองตาม ecosystem เช่น React Router/TanStack Router, TanStack Query, Zustand หรือใช้ Next.js เป็นฐาน full-stack

Vue

npm create vue@latest ✔ TypeScript ✔ Router ✔ Pinia npm install && npm run dev
src/ ├── main.ts ├── App.vue ├── router/ ├── stores/ ├── views/ └── components/

CLI ให้เลือก official tooling เช่น Vue Router, Pinia, Vitest และ ESLint จึงอยู่กึ่งกลางระหว่าง React ที่เลือกเองมาก กับ Angular ที่ framework เตรียมมาเยอะ

Angular

npm install -g @angular/cli ng new my-app cd my-app && ng serve
src/app/ ├── app.ts ├── app.html ├── app.css ├── app.config.ts └── app.routes.ts

มี Router, HttpClient, Forms, DI, testing และ CLI generation เป็น ecosystem เดียว ทำให้โครงโปรเจกต์ของหลายทีมมีรูปแบบคล้ายกัน

คู่กับ ASP.NET Core: แนวทางเหมือนกันทั้งสามแบบ — frontend dev server คุยกับ .NET API ผ่าน CORS/proxy และตอน production จะเสิร์ฟ static build ผ่าน ASP.NET หรือ deploy frontend แยกก็ได้

05เลือกอะไรดี

React เมื่อ

  • ต้องการ ecosystem ขนาดใหญ่และอิสระในการเลือก tool
  • ใช้ Next.js หรือมีแผนต่อยอด React Native
  • ทีมมี convention ที่ชัดและรับภาระการตัดสินใจเองได้

Vue เมื่อ

  • ต้องการเรียนรู้ไวและให้ทีมส่งมอบ feature ได้เร็ว
  • ชอบ SFC, HTML template และ official tooling เช่น Pinia / Router
  • อยากได้ framework ที่มีโครง แต่ไม่หนักเท่า Angular

Angular เมื่อ

  • แอปองค์กรขนาดใหญ่ หลายทีม และต้องการ convention ร่วม
  • ทีมคุ้น TypeScript, DI, service และแนวคิดที่ใกล้ ASP.NET Core
  • ต้องการ tooling ครบและ upgrade path เป็นระบบ

สำหรับทีม .NET: Angular มักรู้สึกคุ้นจาก DI/service, Vue เหมาะเมื่ออยากได้ความเร็วและความเรียบง่าย, React เหมาะเมื่อ ecosystem และความยืดหยุ่นเป็นปัจจัยหลัก

สรุปใจความสำคัญ

React, Vue และ Angular แก้โจทย์เดียวกัน แต่แบ่งความรับผิดชอบระหว่าง “ทีม” กับ “framework” ต่างกัน React เปิดให้ทีมเลือกสถาปัตยกรรมรอบ UI มากที่สุด, Vue ให้ official path ที่พอดีและอ่านง่าย, Angular ตัดสินใจโครงสร้างและเครื่องมือให้มากที่สุดเพื่อความสม่ำเสมอของโปรเจกต์ขนาดใหญ่
